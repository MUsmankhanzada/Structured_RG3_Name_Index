This log records, in the order they were made, every rule and correction built

PART 1 - OUTPUT COLUMNS (final set)

  2.  firstname           forename, incl. regnal numerals and iunior/senior
  3.  firstname_variant   alternative spelling(s) of the forename
  4.  familyname          surname, incl. its nobiliary particle

  7.  relation            "relicta/natus/uxor/filius ..." clause
  8.  zusatz              other bracketed additions; second de-group (origin)
  9.  office              clerical / noble office or title

 11.  reference           "v." (or "s.") cross-reference target
 12.  cf_reference        "; cf. X" cross-reference target
 13.  pages               column numbers of the printed index

--------------------------------------------------------------------------------
STAGE 1 - BASELINE SPLIT
--------------------------------------------------------------------------------

[1.1] Basic two-part split
      Trigger : "Abelinus Vanderlinden 37."
      Rule    : first word = firstname, remainder = familyname,
                trailing digits = pages.

[1.2] "de" as the family-name boundary
      Trigger : "Abraham Abrahe de Nouacuria 43 243 309."
      Rule    : everything before a standalone "de" = firstname;
                "de" and everything after = familyname.
      Effect  : firstname "Abraham Abrahe", familyname "de Nouacuria".

[1.3] Bracketed name variants
      Trigger : "Adam Nicolai de Banchow (Banchcow, Bankow) 37 289."
      Rule    : a bracket following a name holds variant spellings of that
                name. Bracket after the familyname -> familyname_variant;
                bracket after the firstname -> firstname_variant.

[1.4] Entries with no family name
      Trigger : "Agnes (Hospes) 358."
      Rule    : a single name goes to firstname; the bracket is classified
                against it.


--------------------------------------------------------------------------------
STAGE 2 - VARIANT vs ZUSATZ
--------------------------------------------------------------------------------

[2.1] Similarity test for brackets                         -> zusatz column ADDED
      Trigger : "Agnes (Heyncze de Brega) 311." - bracket unrelated to name.
      Rule    : compare bracket content with the name it follows
                (difflib.SequenceMatcher). >= 0.40 -> name variant;
                below -> zusatz.
      Note    : threshold is the module constant SIMILARITY_THRESHOLD.

[2.2] Bracket beginning "de" is always zusatz
      Trigger : "Affra (de Weyspruch) 110."
      Rule    : content whose first two letters are "de" skips the similarity
                test and goes straight to zusatz.

[2.3] Multiple variants inside one bracket
      Trigger : "(Banchcow, Bankow)", "(Aldigherius, Aldericus)"
      Rule    : test each comma-separated item in turn; the FIRST one to
                clear the threshold makes the whole bracket a variant
                (short-circuit - no need to test the rest).

[2.4] Several brackets in one entry
      Trigger : "Goswinus (Goyswinus) Eychlo (Eichloe) 134 236."
      Rule    : each bracket attaches to the nearest preceding name element
                and is classified independently.


--------------------------------------------------------------------------------
STAGE 3 - STRUCTURAL PRIORITY RULES
--------------------------------------------------------------------------------

[3.1] BUG FIX - single-name entries went to the wrong column
      Trigger : "Affra (de Weyspruch) 110." produced familyname "Affra",
                firstname empty.
      Cause   : the de-index fallback only applied at >= 2 words; with one
                word the loop fell through to the familyname branch.
      Fix     : when no split point exists, every word is a firstname.

[3.2] Bracket boundary outranks the "de" rule
      Trigger : "Aldigerius (Aldigherius, Aldericus) Francisci de Florena ..."
      Rule    : if a bracket occurs BEFORE the standalone "de", the firstname
                ends where that bracket opens and the familyname starts after
                it closes. Checked before the de-rule.
      Effect  : firstname "Aldigerius" (+variants), familyname
                "Francisci de Florena".

[3.3] Cross-references                              -> reference column ADDED
      Trigger : "Anton v. Tiboldus.", "Elsa de Villanders v. Elizabeth."
      Rule    : a standalone "v." splits name (left) from reference (right).
                The name part then runs through the normal logic.


--------------------------------------------------------------------------------
STAGE 4 - OFFICES AND INSTITUTIONS
--------------------------------------------------------------------------------

[4.1] Office / institution extraction     -> office + institution columns ADDED
      Trigger : "Erhardus (Gerardus) abb. mon. s. Lamberti in Sewn 110."
      Rule    : scan for the first known role or institution abbreviation
                (longest phrase wins, e.g. "vic. gen." before "vic.").
                Everything before it = name; from it onward = role block.
                Within the role block, the first INSTITUTION term splits
                office from institution.
      Effect  : office "abb.", institution "mon. s. Lamberti in Sewn".
      Added   : "abb." alongside "abbat.".
      Note    : this runs before the name logic, so a "de" inside an
                institution ("mon. de Harbeyser") never reaches the name
                splitter.

STAGE 5 - FIRST FULL-CORPUS AUDIT (3,708 rows)
--------------------------------------------------------------------------------

[5.1] Page ranges with dashes - DATA LOSS
      Trigger : "... 385—402.", "... 70 158 304—307 371."
      Problem : the page regex walked back only over space-separated numbers,
                so it captured "402" and "307 371" - losing 70 and 158.
      Fix     : page tokens may be ranges joined by - , – or —.

[5.2] "; cf. X" clauses - DATA LOSS         -> cf_reference column ADDED
      Trigger : "Clemens de Alsentz 78; cf. Nicolaus Frederici de A."
      Problem : the line ends in a letter, so no pages were found and the
                whole tail landed in familyname.
      Fix     : strip the cf. clause BEFORE page extraction, because the
                pages sit in front of it.

[5.3] "s." as "siehe" (see)
      Trigger : "Venslaus, Vinceslaus s. Wenceslaus."
      Problem : "s." is "sancti" in 48 other entries ("mon. s. Lamberti").
      Rule    : treat "s." as a reference separator ONLY when the entry
                contains no digits at all. Isolates exactly the one case.

[5.4] Comma-listed forenames in cross-references
      Trigger : "Guillelmus, Guilermus v. Wilhelmus."
      Problem : "Guilermus" was going to familyname.
      Rule    : in a pageless v./s. entry, "A, B v. C" gives firstname A,
                firstname_variant B, reference C.

[5.5] OCR line-break hyphens (14 rows)
      Trigger : "Con-stancianen.", "Martin- kowo", "Eppen-steyn", "Ba- uarie"
      Rule    : join hyphen (+ optional space) between two LOWERCASE letters.
      Guard   : lowercase-only, so the deliberate suffix variants
                "(-berg, -berch)" and "(-kink, -kinc)" are untouched.
                Those are also classified as variants explicitly, by a
                leading-hyphen rule, not by similarity score.

[5.6] Popes and regnal numerals (12 rows)
      Trigger : "Gregorius XII. (Angelus, Errorius) pp. 9 12 13."
      Problem : familyname became "XII. pp." and the variants went to zusatz.
      Rule    : roman numerals stay with the firstname; "pp." is an office.

[5.7] Cardinal titulature
      Trigger : "Alamannus tit. s. Eusebii presb. card. 39."
      Problem : split at "presb.", stranding "tit. s. Eusebii" in the name.
      Added   : tit. card. diac. patr. prior priorat. prep. prepos. dec.
                decan. custos custod. scholast. scolast. thesaurar. can.
                capit. natus nuncup. el. resp. quondam

      RESULT  : rows with no pages 30 -> 26, and all 26 are genuine
                cross-references. No row left without pages AND reference.

STAGE 7 - SECOND AUDIT: ALIAS AND RELATION
--------------------------------------------------------------------------------

[7.1] Alias markers (115 rows)                       -> alias column ADDED
      Trigger : "Albertus Beyer al. Steneken 40."
                "Andreas dict. Kelermaister 48."
      Problem : "al." / "dict." are alias / dictus ("called"), not offices.
                They were being swallowed into familyname; "Andreas dict.
                Kelermaister" ended up with no real familyname at all.
      Rule    : markers "al." "dict." "sive" "seu" introduce an alias.
                They stack ("al. dict."), brackets stay attached to their
                alias, and multiple aliases join with "; ".
      Key point : a "de ..." AFTER alias content is the territorial family
                name and is handed BACK to the name -
                "Nicolaus Henrici al. dict. Schilchin (Schibchin) de
                Cruczenaco" -> familyname "de Cruczenaco", alias
                "Schilchin (Schibchin)".

[7.2] Period-separated page runs - DATA LOSS
      Trigger : "Arpinus de Collis de Alexandria 58. 345."
                "Georgius Lichtenberg 127. 256."
      Problem : captured only the last number; the first was left in
                familyname.
      Fix     : page tokens may be separated by whitespace and/or a period.

[7.3] Further office terms
      Added   : mag. / mag. gen. / ord. / priorissa / duxissa / ducis /
                princeps / lantgr. / bar. / imp. / scol. / precept. /
                thesaur. / not. / not. ap. sed. / ap. sed.

[7.4] Relation clauses (34 rows)                  -> relation column ADDED
      Trigger : "Agnes relictæ Herbordi Kuykens de Tremonia 38."
                "Elisabet Vlrici bar. de Haenow uxor 107."
      Rule    : markers relict*/relect* (prefix match), natus, nata, uxor,
                filius, filia. Marker at the END -> everything after the
                forename is the clause; marker mid-entry -> from the marker on.
      ORDER   : this runs BEFORE the office scan, because the clause itself
                contains office words ("bar.") that would otherwise shred it.
      Note    : the prefix form was needed - OCR yields relictæ, relictä,
                relictā and relecta.

[7.5] Generational suffixes
      Trigger : "Fredericus iunior lantgr. Thuringie 13."
      Problem : familyname became "iunior".
      Rule    : iunior / junior / senior / iun. / sen. stay with the
                forename, like regnal numerals.

[7.6] OCR typo "dc" for "de"
      Trigger : "Bertoldus dc Kuczeleibin (Kuczelewen) 247 389."
      Rule    : token-level normalisation dc -> de.

STAGE 9 - THIRD AUDIT: IN-WORD BRACKETS
--------------------------------------------------------------------------------

[9.1] Editorial in-word brackets (42 rows) - NAMES WERE BEING SHATTERED
      Trigger : "Je(ronimus) Rutili"        -> firstname "Je"
                "Johannes Hil(le)manni"     -> familyname "Hil manni"
                "Fridericus Deys(t)"        -> "(t)" lost entirely
      Cause   : a bracket glued to a word with no space is editorial - it
                marks letters INSIDE one word - but the tokenizer split on it.
      Disambiguator (splits the corpus 41 / 1):
                lowercase content -> in-word letters
                uppercase content -> a real variant that lost its space
                                     ("Diick(Deyk)" -> a space is inserted)
      Rule    : in-word parentheses are replaced by sentinel characters
                before tokenizing and restored as each word token is built.

[9.2] REVERSAL - no invented variants
      First done : the contracted form was recorded as a variant
                   ("Jeronimus" + variant "Je").
      User note  : the raw entry asserts no such variant; the brackets
                   expand an abbreviation, they do not record an alternative
                   attested name.
      Corrected  : nothing is written to the variant columns from an in-word
                   bracket.
      Effect     : firstname_variant 135 -> 131, familyname_variant 320 -> 291
                   (the ~33 fabricated entries removed).

[9.3] Source text kept verbatim (user request)
      Rule    : the bracket is NOT expanded. The printed form is preserved:
                  Je(ronimus)   Hil(le)manni   Deys(t)   de Bal(l)ionibus
      Both mechanisms can co-occur in one entry:
                "Wenc(z)eslaus (Vinceslaus) Thyen (Thiem, Thien)"
                -> firstname "Wenc(z)eslaus", firstname_variant "Vinceslaus"

[9.4] Unbalanced brackets (2 rows)
      Trigger : "Schaczel (Scheczel 123 164."          (never closed)
                "de Blaetzhem (Blatzhem, (Blaeczheim)" (doubled opener)
      Rule    : stray openers inside an open group are dropped; an unclosed
                group is closed before the page run.

[9.5] Bare "al" without a period (2 rows) + alias bug
      Trigger : "Johannes Wintheri de Rudensheim al de Gisenheim 238 255."
      Problem : alias empty, familyname "de Rudensheim de Gisenheim".
      Cause   : ANY "de" was treated as starting a territorial surname.
      Fix     : "de" ends the alias only if alias content was already
                collected; directly after the marker it belongs to the alias.
      Effect  : familyname "de Rudensheim", alias "de Gisenheim".

[9.6] Further office terms
      Added   : archipresb. / castellanus / heres

STAGE 10 - FOURTH AUDIT: CASE SENSITIVITY AND PARTICLES
--------------------------------------------------------------------------------

[10.1] Capitalised role words are SURNAMES (4 rows)
      Trigger : "Johannes Rex 18."  "Hermannus Ducis 131."
                "Johannes Ducis 152."  "Marcus Wenceslai dict. Dux 365."
      Evidence: of 437 office blocks, EVERY genuine one begins lowercase
                (ep. x107, abb. x80, dux x38, rex x8, ...). The only
                capitalised ones were these four surnames.
      Rule    : an office abbreviation matches only when printed lowercase.
      Note    : this is the general form of [8.1] - position 0 was only a
                proxy for what is really a capitalisation rule.

[10.2] Bracketed nobiliary particle (9 rows)
      Trigger : "Bertoldus (de) Cellis 65 254."
      Problem : the bare "de" went to zusatz, severing the particle.
      Rule    : a bracket holding only de/von/van/di/del/della is emitted as
                a WORD token, kept verbatim, and marks the family-name
                boundary like a plain "de".
      Effect  : familyname "(de) Cellis".

================================================================================
PART 6 - MAINTENANCE NOTES
================================================================================

  * Keep the reconstruction audit (PART 2, [11.1]) as a standing test. It is
    the single most effective check - any new rule that silently eats text
    shows up immediately.

  * Lookup tables are deliberately explicit, not generalised. Extending them
    is a one-line edit:
        PAGE_FIXES         page-run corrections
        OCR_SPACE_JOINS    space-break joins
        TOKEN_FIXES        token typos (currently dc -> de)
    Before adding a key, confirm the substring occurs exactly once in the
    corpus, or it may misfire on another entry.

  * Vocabulary lists that may need extending for other volumes:
        PERSON_OR_ROLE_PREFIXES   offices and titles
        INSTITUTION_PREFIXES      churches, monasteries, hospitals
        ALIAS_MARKERS             al. dict. dictus dicta sive seu
        RELATION_MARKERS          natus nata uxor filius filia
        RELATION_PREFIXES         relict- relect-
        NAME_SUFFIXES             iunior junior senior iun. sen.
        NOBILIARY_PARTICLES       de von van di del della

  * Office terms are matched LOWERCASE ONLY [10.1]. Adding a term that also
    occurs as a surname is therefore safe, but verify the assumption still
    holds if a new volume prints offices differently.

  * SIMILARITY_THRESHOLD is 0.40. Lowering it moves zusatz entries into the
    variant columns; raising it does the reverse. One known borderline case:
    "Balduinus (Baldwinus) de Diick(Deyk)" - "Deyk" scores below 0.40
    against "Diick" and lands in zusatz, although the glued bracket suggests
    it is a variant.

  * raw_entry stores the source text with mojibake repaired but WITHOUT the
    OCR joins, hyphen rejoins and page corrections. Searching raw_entry for
    "Sle sie" or "690" will therefore still match, while the parsed columns
    carry the corrected forms. This is deliberate - the source reading stays
    inspectable.
